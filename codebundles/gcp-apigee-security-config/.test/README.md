# GCP Apigee Security and Configuration Health — Test Infrastructure


## Standard task vocabulary

Every `gcp-apigee-*` bundle declares the same tasks, with the same
responsibilities and the same exit semantics — `task --list` is byte-identical
across all five, so moving between them costs nothing.

```
default  →  ci → check-unpushed-commits → build-infra → test-live
                → generate-rwl-config → run-rwl-discovery
ci       →  test-offline → test-render → validate-generation-rules
                → check-shared-drift
clean    →  check-and-cleanup-fixtures → clean-rwl-discovery
```

| Task | What it does |
|---|---|
| `ci` | Everything that needs no cloud, no credentials and no spend. Gates a PR. |
| `test-offline` | Check logic against canned API responses. |
| `test-render` | Templates through runwhen-local's jinja2 configuration. |
| `validate-generation-rules` | Generation rules against the published schema. |
| `check-shared-drift` | Fails when a file meant to be identical across the Apigee bundles has diverged. |
| `build-infra` | Creates this bundle's fixtures (healthy + deliberately broken). |
| `test-live` | Runs the checks against those fixtures and asserts on what they report. |
| `check-and-cleanup-fixtures` | Removes this bundle's fixtures and verifies none survive. |
| `clean` | Fixtures + local discovery output. Needs **no** RunWhen Platform credentials. |
| `bootstrap-prerequisites` | Idempotent: APIs, VPC, peering range, the Apigee org, both environments and the runtime instance. Called by `build-infra`. |
| `preflight` | Asserts the substrate contract by name before any fixture is created. |
| `destroy-prerequisites` | Removes that substrate. Refuses while the org still exists. |
| `run-rwl-discovery` | RunWhen Local discovery, on a pinned image checked for the Apigee resource types. |

Implementation sub-steps (`build-terraform-infra`, `bootstrap-apigee-fixtures`,
`generate-certs`, …) are `internal: true`. They are still runnable — use
`task --list-all` to see them — but they are out of the operator's way.

`bootstrap-prerequisites` / `destroy-prerequisites` run the byte-identical
`apigee_prerequisites.sh` present in all five bundles, so no bundle depends on
another having been run first and the order they are torn down in does not
matter. That script is check-then-create over `gcloud`/REST rather than
Terraform, because five Terraform states cannot each own the same VPC, address
and peering — see its header for the full reasoning.

The substrate includes **both Apigee environments and the runtime instance**,
not just the org. An `EVALUATION` organization is capped at two environments
and one instance, and four of the five bundles need those environments — a
capped resource is shared by definition, so it cannot belong to one bundle`s
fixtures. `build-infra` calls `bootstrap-prerequisites` itself and then
`preflight`, so which bundle you run first is no longer something to know.

> **`apigee-env-unattached-*` being unattached is a fixture, not a defect.** It
> is `gcp-apigee-environment-health`s known-positive for
> `check_instance_attachments`, and `gcp-apigee-proxy-health`s second
> environment for the cross-environment revision-drift fixture. Attaching it
> "to tidy up" makes that check pass because there is nothing left to find.
> `preflight` warns if it has been attached.

## Start here: the tiers that need no cloud and no credentials

These are the tiers that gate a PR, they cost nothing to run, and they are the
ones to run first.

```bash
./validate-all-tests.sh    # both tiers below
./offline/run.sh           # 130 assertions: check logic + static wiring
./render/run.sh            # 19 assertions: templates through runwhen-local's jinja2
```

or `task ci` / `task test-offline` / `task test-render`.

- **`offline/`** runs every check script against canned Apigee Management API and
  Cloud Monitoring responses and asserts on what it reports, then statically
  checks the generation rule, both templates and the runbook wiring. Fixtures are
  generated by `offline/fixtures.sh` from the Apigee v1 **discovery document**,
  never from what the code expects to see — read that file's header before
  changing one.
- **`render/`** renders the SLX and taskset templates through the same jinja2
  configuration runwhen-local uses. It needs `jinja2` and `pyyaml`; without them
  it **skips loudly** rather than reporting a success it did not earn.

Everything below this point needs a GCP project and will spend money.

## Overview

This bundle is a **read-only guest** on a shared Apigee X organization. An Apigee
org is one-per-project and takes ~45 minutes to create, so the org, its runtime
instance and its environments are provisioned by the
`gcp-apigee-environment-health` sibling's bootstrap — including
`apigee.googleapis.com` and `monitoring.googleapis.com`, which that bundle owns
in its own Terraform state.

The Terraform here therefore provisions only a read-only service account
(`roles/apigee.readOnlyAdmin` + `roles/monitoring.viewer`) and, optionally, a key
for it. It deliberately enables no APIs: doing so put one GCP resource under two
Terraform states, and `task clean` would then have attempted to disable the
Apigee API underneath the live org that three other bundles depend on.

## Prerequisites

1. A GCP project where `gcp-apigee-environment-health` has already run its
   bootstrap, so an Apigee organization exists and the APIs are enabled.
2. Permission to create a service account and grant project IAM roles.
3. `gcloud` CLI configured.
4. `terraform`, `docker` and `task`. The generation-rule validation also needs
   `curl`, `yq`, `ajv` and `jq`.

## Setup

1. Create `terraform/tf.secret`. This is the shared credential contract all four
   Apigee bundles read via `load-credentials.sh`, which accepts either spelling
   of the organization and warns when an ambient environment variable disagrees
   with the file — the drift a shared, one-per-project org makes easy:

   ```bash
   export GOOGLE_APPLICATION_CREDENTIALS="/path/to/bootstrap-key.json"
   export TF_VAR_project_id="your-gcp-project-id"
   export TF_VAR_org_id="organizations/your-apigee-org"   # or APIGEE_ORG="your-apigee-org"
   ```

2. Provision the reader:

   ```bash
   task build-infra
   ```

3. Write out the reader's key for discovery to use:

   ```bash
   cd terraform && terraform output -raw apigee_reader_key | base64 -d > ../gcp.json.secret
   ```

   The private key is held in Terraform state. If that is not somewhere a
   credential may live, set `create_reader_key = false` and mint one out of band
   instead:

   ```bash
   gcloud iam service-accounts keys create gcp.json.secret \
     --iam-account="$(cd terraform && terraform output -raw apigee_reader_service_account_email)"
   ```

4. Run discovery and validate the generation rule:

   ```bash
   task default
   ```

## Teardown

```bash
task clean
```

Destroys the reader service account and its IAM bindings only. The Apigee
organization, its runtime instance and the project's API enablement are **not**
managed here and survive.

## What a live run can and cannot demonstrate

On a shared org built by the siblings, several checks get their known-positives
for free; others need fixtures that nothing currently creates:

| Check | Fires against the shared org? |
|---|---|
| `check_target_vhost_config` — plaintext backend | yes — env-health's target servers are `protocol = "HTTP"` with no `sSLInfo` |
| `check_quota_limits` — no quota configured | yes — product-governance's auto-approve product |
| `check_quota_limits` — `approvalType: auto` | yes — same product |
| `check_quota_limits` — quota ≥ threshold | no — the highest fixture quota is `1000`; reachable with `QUOTA_ABUSE_THRESHOLD=500` |
| `check_app_access` — all three modes | no — no wildcard scopes and no revoked keys exist; needs two REST fixtures |
| `check_security_score` | **not reachable on an EVALUATION org at all** |

That last row is a property of Apigee, not a gap in this bundle:
`apigee.googleapis.com/security/*` only populates with the paid **Advanced API
Security** add-on, so on a trial or evaluation org those metrics are absent and
the check is exercised offline only. `check_security_score.sh` already treats
that absence correctly — no data means "not measured", never "measured as zero
risk" — but its live behaviour cannot be demonstrated without the add-on.

There is no keystore/TLS alias expiry scenario here. That check was removed from
this bundle as a duplicate of `gcp-apigee-environment-health`'s
`check_keystore_cert_expiry.sh`, which gates on the same resource type — see the
bundle README.
