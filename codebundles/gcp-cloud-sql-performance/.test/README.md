# gcp-cloud-sql-performance — Test Infrastructure

Tests discovery and template rendering for the `gcp-cloud-sql-performance`
codebundle.

## What the fixtures create

`terraform/` provisions two Cloud SQL (MySQL) fixtures in the target project,
covering healthy and unhealthy states:

| Fixture | State | Purpose |
|---|---|---|
| `sql-perf-healthy-*` | healthy | Small fixed tier with automatic storage increase enabled and a database |
| `sql-perf-overutilized-*` | over-utilized / storage-risk | Small tier with automatic storage increase disabled (exercises the storage-fill and utilization checks) |

Note: utilization, performance, and storage-risk checks rely on Cloud
Monitoring data generated by real traffic, so the presence of metric-based
issues depends on load being sent to the instances. The `overutilized` fixture
disables autoresize to deterministically exercise the storage-risk detection.

## Usage

```bash
cd .test

# 1. Credentials: create terraform/tf.secret with:
#    export GOOGLE_APPLICATION_CREDENTIALS="/path/to/svc.json"
#    export TF_VAR_project_id="my-gcp-project"
#    and place the same key at .test/gcp.json.secret for RunWhen Local

# 2. Provision fixtures
task build-infra

# 3. Generate config + validate rules/tests
task generate-rwl-config GCP_PROJECT_ID=my-gcp-project RW_WORKSPACE=my-workspace
task validate-all-tests
task validate-generation-rules

# 5. Tear everything down
task clean
```

`task` (default) runs: check-unpushed-commits → build-infra →
generate-rwl-config → run-rwl-discovery → validate-generation-rules.

## Requirements

- `terraform`, `gcloud`, `docker`, `jq`, `yq`, `ajv`, `curl`
- GCP service account with `roles/cloudsql.admin`, `roles/monitoring.viewer`,
  and `roles/cloudsql.client` on the test project (used by Terraform to create
  the Cloud SQL fixtures)
